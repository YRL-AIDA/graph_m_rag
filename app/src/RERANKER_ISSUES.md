# Reranker-стратегия: известные проблемы (для будущего исправления)

Документ описывает причины, по которым стратегия `reranker`
(`use_reranker=True` в `/ask-document`) может работать хуже `baseline`.
Все проблемы относятся к `app/src/api.py` в функции `ask_document`.

Номера строк могут сдвигаться; ориентируйтесь на имена переменных и сниппеты.

---

## 1. Баг: неверная индексация после переранжирования

**Критичность:** высокая.

**Место:** блок «Apply reranking if enabled…», строка вида
`answer_copy = answers[res.message_id].copy()`.

**Суть:**

```python
for res in rerank_messages[:limit]:
    answer_copy = answers[res.message_id].copy()
    ...
```

`res.message_id` — это индекс внутри списка `documents_to_rerank`, в который
попадают **только первичные блоки**. Но список `answers` устроен иначе: для
элементов image/table с Neo4j-контекстом связанные ответы
(`parent_answer` / `caption_answer` / `footnote_answer`, у которых
`is_related_context=True`) добавляются в `answers` **до** первичного блока.

Порядок в цикле формирования результатов:

1. создаётся первичный `answer` (`is_related_context=False`);
2. если есть `neo4j_context`, в `answers` добавляются связанные блоки
   (`answers.append(parent_answer)`, `answers.append(caption_answer)`,
   `answers.append(footnote_answer)`);
3. в самом конце итерации добавляется первичный блок:
   `answers.append(answer)` и `documents_to_rerank.append(message)`,
   а также `search_results_map[idx] = answer`.

В результате:

- `answers` содержит перемешанные записи (связанные + первичные);
- `documents_to_rerank` содержит только первичные;
- `res.message_id` индексирует `documents_to_rerank`, но применяется к `answers`.

Когда Neo4j-контекст присутствует, `answers[res.message_id]` указывает не на тот
блок: reranker может положить в топ подпись/сноску вместо первичного текста
или перепутать `score`/содержимое.

**Правильное поведение:** использовать готовую карту `search_results_map`,
которая заполняется корректно (`search_results_map[idx] = answer`):

```python
answer_copy = search_results_map[res.message_id].copy()
```

**Дополнительно:** стоит добавить тест/assert, что
`len(documents_to_rerank) == len(search_results_map)`, и что `answers`
после переранжирования содержит только первичные блоки.

## 2. Потеря связанного контекста после переранжирования

**Критичность:** средняя.

**Место:** `answers = reranked_answers` (после цикла переранжирования).

**Суть:**

Переранжирование полностью заменяет список:

```python
answers = reranked_answers
```

Все отдельные связанные блоки (`is_related_context=True`: parent, caption,
footnote) выбрасываются. В `baseline` они сохраняются через uniform region cap
(блок «Uniform region cap (all strategies)»), который пропускает
`is_related_context=True` блоки вместе с их первичным блоком.

Reranker сохраняет только поле `neo4j_context` внутри первичного блока
(оно рендерится как `<related_element>` внутри `<block>`), но теряет отдельные
блоки, у которых могли быть свои картинки (например, изображение подписи).

**Правильное поведение:** после переранжирования восстановить связанные блоки
для выбранных первичных (например, по `related_to_element_type` / `element_index`),
либо переранжировать только первичные блоки, а связанные добавлять обратно
по ссылке на первичный.

## 3. Reranker ранжирует текстовое представление, baseline — мультимодальный эмбеддинг

**Критичность:** средняя (зависит от сервиса reranker).

**Место:** формирование `documents_to_rerank` (объект `message`) в цикле
результатов.

**Суть:**

- Baseline-порядок идёт от Qdrant, где эмбеддинг считается через
  `get_image_text_embedding_base64(text, image_base64)` — учитывает и картинку,
  и текст.
- Reranker получает `message`, где для image/table в основном передаётся текст
  вида `Figure | Image: | caption...` (изображение опционально, если сервис его
  поддерживает).

Если reranker-сервис текстовый или слабо обучен на домене, для «визуальных»
документов (логотипы, графики, таблицы) его топ-30 будет хуже эмбеддингового.

**Что проверить/исправить:**

- Поддерживает ли reranker-сервис поле `image` (multimodal) и реально ли он его
  использует при ранжировании.
- Если reranker текстовый — передавать ему более информативный текст
  (описания картинок, OCR, table_body), а не только `Figure | Image:`.

---

## 4. Кросс-энкодер может быть хуже откалиброван под корпус

**Критичность:** низкая/средняя (общее свойство reranker-подхода).

**Место:** логика выбора топ-`limit` (`rerank_messages[:limit]`).

**Суть:**

Оба пути забирают `search_limit = max(limit * 5, RERANKER_TOP_N) = 150`
кандидатов, но отбирают топ-30 по разным скорам:

- baseline — косинусная близость эмбеддингов Qdrant;
- reranker — скор кросс-энкодера.

Если reranker не дообучен на домен/язык документа, он может «переоценивать»
правдоподобные, но неверные пассажи. Это не баг кода, а ограничение модели.

**Что проверить/исправить:**

- Сравнить качество reranker на контрольной выборке отдельно от бага №1.
- При необходимости дообучить/заменить reranker или добавить гибридное
  ранжирование (например, комбинация embedding-скора и reranker-скора).

---

## Порядок исправления (рекомендуемый)

1. Исправить баг №1 (`answers[res.message_id]` → `search_results_map[...]`).
2. Восстановить связанный контекст (проблема №2).
3. Перепроверить качество reranker на выборке и только затем разбираться
   с №3 и №4.
