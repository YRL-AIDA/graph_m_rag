# Graph-M-RAG — демонстрационное приложение

Прототип демо-приложения для показа системы **Graph-M-RAG** потенциальному
заказчику. Показывает, что умеет система, как она отвечает на вопросы по
документам и чем графовое обогащение лучше классического RAG.

## Что демонстрирует

| Возможность | Где во вкладках |
|---|---|
| **Пайплайн технологии**: PDF → регионы → эмбеддинги → структурный граф → семантический граф → ответ | «Пайплайн» (статика) + полоса пайплайна, анимирующаяся при вопросе |
| **Разбиение на регионы**: PDF-страница с цветными bbox регионов (текст, заголовки, таблицы, изображения), легенда, клик по региону → его текст | «Документ и регионы» |
| **Структурный граф**: порядок чтения (ORDER), иерархия (PARENT), секции — визуализация соседей из контекста ответа | «Графы» |
| **Семантический граф**: сущности (person/org/…) и сообщества (rating) по вопросу | «Графы», чипы во «Вопросе» |
| **Состав контекста**: сколько блоков пришло из Qdrant / структурного графа / семантического графа | «Вопрос» (бары композиции) |
| Вопросно-ответный диалог + тайминги пайплайна | «Вопрос» |
| **Доказательства на странице**: подсветка регионов, использованных для ответа | «Вопрос» → «Показать на странице» |
| **Сравнение стратегий**: baseline RAG vs графовые стратегии, с составом контекста | «Сравнение» |
| Загрузка PDF и статус обработки | «Файлы» |

Три ключевые технологии подсвечены отдельными цветами во всём интерфейсе:

- **Разбиение на регионы** — оранжевый `#f39c12` (вкладка «Документ и регионы»);
- **Структурный граф** — зелёный `#3fb950` (ORDER/PARENT/SECTION);
- **Семантический граф** — фиолетовый `#7c5cff` (Entity/Community).

## Стратегии (в сравнении)

| Стратегия | Флаги `/demonstration` | Суть |
|---|---|---|
| `baseline` | `strategy=baseline` | Классический RAG: топ-30 блоков Qdrant → LLM |
| `semantic` | `strategy=semantic` | + сущности и сообщества семантического графа |
| `structural` | `strategy=structural` | + соседние регионы по порядку чтения (ORDER-walk) и родительские элементы |
| `both` | `strategy=both` | + BFS-обход графа (полный Graph-M-RAG) |

Демо проксирует **`POST /demonstration`** основного API — специальный
демо-эндпоинт, который принимает имя стратегии (`strategy`) и сам раскладывает
его на флаги графов `/ask-document` (`use_semantic_graph`,
`use_structured_graph`). Это избавляет демо-интерфейс от знания внутренних
флагов. Эндпоинт также отвечает на **GET** (query-параметры) для быстрой
проверки в браузере:

```
/demonstration?file_hash=...&question=...&strategy=semantic
```

## Архитектура

```
Браузер
   │  HTTP (static + JSON API)
   ▼
Demo server  (demo/backend/demo_server.py, :8282)
   │  прокси: /upload-pdf, /demonstration, /uploaded-files, /health
   ▼
Graph-M-RAG API  (:9191)
   ├─ Qdrant   — векторный поиск (документы, эмбеддинги сущностей/сообществ)
   ├─ Neo4j    — структурный (ORDER/PARENT/SECTION) и семантический (Entity/Community) графы
   ├─ MinerU   — извлечение структуры PDF (текст, таблицы, изображения, OCR)
   └─ Qwen3-VL — генерация ответа (мультимодальная, работает с таблицами и картинками)
```

Демо-сервер — тонкий прокси: он не дублирует бизнес-логику, а переиспользует
реальный API Graph-M-RAG и добавляет поверх слой сравнения, парсинг контекста
в JSON для визуализации и веб-интерфейс.

## Запуск

```bash
# 1) Запущен основной сервис Graph-M-RAG на :9191 (см. docker-compose в корне).

# 2) Запустить демо (бэкенд-режим):
.venv/bin/python demo/backend/demo_server.py --port 8282

# Открыть: http://localhost:8282
```

**Режим без инфраструктуры (для презентации без серверов):**

```bash
.venv/bin/python demo/backend/demo_server.py --port 8282 --mock
```

В `--mock`-режиме интерфейс полностью работает на демо-данных (вкладки,
сравнение, граф), но ответы помечены как демонстрационные.

Дополнительные опции:

```bash
--base-url http://host:9191   # если Graph-M-RAG на другом хосте
```

## Сценарий демонстрации (5 минут)

1. **Пайплайн** → проведите по диаграмме: разбиение на регионы → структурный
   граф → семантический граф. Это общая картина технологии.
2. **Документ и регионы** → выберите загруженный PDF. Покажите цветные
   регионы на странице (текст/заголовки/таблицы/изображения), кликните по
   региону — видно его тип и текст. Так наглядно видно «разбиение на регионы».
3. **Файлы** → при необходимости загрузите PDF (1–3 мин на обработку).
4. **Вопрос** → выберите `Both Graphs`, задайте вопрос («Какой был общий
   доход компании?»). Покажите **полосу пайплайна** — 6 шагов загораются
   последовательно. После ответа покажите **бары композиции контекста**
   (Qdrant/структурный/семантический) — видно, что графы реально участвуют.
5. **Показать на странице** → кнопка переключает на PDF с подсвеченными
   зелёным регионами-доказательствами (страницы, из которых взят ответ).
6. **Графы** → вкладка «Графы»: структурный граф (порядок чтения ORDER,
   связи PARENT) и семантический граф (сущности, сообщества) по вопросу.
7. **Сравнение** → один и тот же вопрос на 4 стратегиях. Покажите, что
   у `baseline` (обычный RAG) нет семантических/структурных источников, а у
   графовых стратегий они есть — и ответ точнее.

## Замечания

- Демо не выполняет оценку качества — для этого есть `app/tests/evaluate_strategies.py`.
- Прокси передаёт файлы и запросы без изменений; весь объём контекста хранится
  на стороне Graph-M-RAG.
- `--mock` генерирует канонический ответ и подписывает его как демонстрационный,
  чтобы не путать заказчика с реальным поведением системы.
